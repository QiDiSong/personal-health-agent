# Apple 健康每日同步

这个版本接收你授权导出的每日汇总。Python 脚本只上传 JSON，不会读取 iPhone、Apple Watch 或 Apple 账号。这里没有原生 iOS 后台 HealthKit 集成，也不是 Apple 或 OpenAI 的官方 Health 插件。快捷指令需要在你的 iPhone 上创建、授权和运行；本仓库没有已经在真机验证的通用六指标自动采集快捷指令。

## 先准备服务和权限

1. 按项目 README 启动 API，并设置自己的强随机 `HEALTH_API_TOKEN`，至少 32 个可打印 ASCII 字符且不能包含空白。不要把令牌放进聊天、截图或共享快捷指令。
2. iPhone 使用的服务地址必须是手机能访问、证书有效的 **HTTPS** 地址，例如 `https://health.example.com`。这个域名只是占位示例，需要换成你实际部署的地址。手机上的 `127.0.0.1` 指向手机本身，不能连接电脑。局域网访问也应配置 HTTPS。
3. 查询 `GET /v1/profile`，核对保存的时区。默认 `Asia/Shanghai`；下面的日期步骤以此为例。手机“设置 → 通用 → 日期与时间”的时区应与档案一致。旅行或换时区后先核对边界，不要直接沿用按另一个时区生成的日期。
4. 在 iPhone“健康 → 浏览”打开要导出的指标，进入“数据来源与访问权限”（部分系统在指标页底部），检查来源、单位和日期。给每个指标选一个可信来源，例如只用 Apple Watch 的步数，或只用 iPhone 的步数。固定选择并在私人记录中记下名称和生效日期。
5. 打开“快捷指令 → 快捷指令 → ＋”，命名“健康每日同步”。添加下面的“查找健康样本”动作，首次手动运行时，**由你自己在系统提示中允许读取所需健康类型**。不同 iOS 版本的动作和权限名称可能略有不同，可搜索括号中的英文名称。没有允许、没有结果或手机锁定时无法读取，都应停止该指标的同步。可在“健康 → 右上角头像 → App/应用与服务 → 快捷指令”检查或撤回权限；部分版本入口在系统隐私设置中。

Apple 健康页面对来源的优先级处理，**不代表“查找健康样本”的所有结果已经合并去重**。不能把手表、手机和其他 App 的步数或能量简单相加；接口也不会替你对原始样本去重。这里的 `source: apple_health` 表示你已经在设备端选定来源并整理过的汇总，不表示服务连接了 HealthKit。若只选手表，未戴表时的手机步数不会自动补入；这是选择单一来源的取舍。需要与健康 App 的合并总数完全一致时，先在该 App 核对总数，再手动输入确认值。

## 创建一个可核对的步数快捷指令

先只做一个日期、一个指标，手动查看结果正确后再增加其他指标。首次选一个已经结束的日期；当天的数值只是截至运行时的快照。

1. 添加“询问输入”（Ask for Input），类型选“日期”，提示“要同步哪一天？”；添加“格式化日期”（Format Date），自定格式 `yyyy-MM-dd`，将结果存为变量“日期键”。避免使用表示周年的 `YYYY`。
2. 以选择的日期添加“调整日期”（Adjust Date），操作选择获取当天的开始时间，存为“日开始”；再对它添加一天，存为“次日开始”。确认两者显示为该档案时区的 `00:00`。如果你的系统没有“获取当天开始”选项，在本例时区可用“文本”动作组成 `[日期键]T00:00:00+08:00`，接“从输入中获取日期”（Get Dates from Input），再添加一天。这个固定偏移只适用于本例的 `Asia/Shanghai`，不能照搬到有夏令时的时区。
3. 添加“查找健康样本”（Find Health Samples）：类型“步数”，开始日期范围设为“日开始”到“次日开始”，来源只选前面确定的**一个**来源，不设置结果条数上限。若版本不提供“来源”筛选，使用“重复每一项”（Repeat with Each）及“获取健康样本的详细信息”（Get Details of Health Samples）读取来源，仅保留完全匹配的来源；若无法读取来源，则停止自动求和，改为在健康 App 核对后手动输入该日总数。
4. 核对保留样本的开始、结束日期：只统计 `开始 >= 日开始` 且 `开始 < 次日开始` 且 `结束 <= 次日开始` 的样本，排除恰好在次日开始的样本。遇到跨日样本时不要直接把整个样本归入某一天；应改用已核对的日总数，或先进行有依据的分日处理。若范围筛选在你的版本会包含边界外结果，用“如果”（If）检查日期后才把其数值加入列表。
5. 用“获取健康样本的详细信息”取“值”，单位确认是“步”；对数值列表用“计算统计数据”（Calculate Statistics）选择“总和”，存为“步数合计”。**只有明确为不重复的增量样本才可以求和**，不能对累计日快照再求和。同一来源仍有重叠或重复、无法判断增量语义时，改用手动核对的日总数。列表为空就停止，不生成零步记录。先用“快速查看”（Quick Look）核对日期、选定来源及合计。
6. 添加“词典”（Dictionary），键 `date` 为“日期键”（文本），`metric` 为文本 `steps`，`value` 为“步数合计”（**数字**）。把这个词典放进“列表”（List），存为“每日观测”。
7. 再添加外层“词典”：`source` 为文本 `apple_health`，`observations` 为“每日观测”列表。用“快速查看”确认它是嵌套对象和数组，而不是把一段 JSON 文本塞进字符串。参考下方请求形状。这个预览包含健康数据，只在自己的手机上查看。
8. 添加“URL”，填 `https://你的真实域名/v1/sync`；添加“获取 URL 内容”（Get Contents of URL），方法选 `POST`。请求头添加 `Authorization`，值为 `Bearer ` 后接你的令牌；另加 `Content-Type: application/json`。请求体选 JSON：添加文本字段 `source=apple_health`，添加数组字段 `observations`，数组中的词典填入第 6 步三个字段。若当前版本允许将整个词典作为 JSON 请求体，直接传第 7 步外层词典；若编辑器不支持变量词典或嵌套数组，不要退回表单编码，使用下方的导出文件加 Python 上传路径。
9. 手动执行并核对 `source` 和 `upserted` 响应。第一次只发一项，再从 API 或聊天工具查询同一天的摘要，确认步数一致。在遇到 401、422、网络错误或非成功响应时停止并修正，不在共享日志中保存请求头、原始数据或响应全文。iOS 的 URL 动作可能跟随重定向；配置直接返回 API 响应的最终 HTTPS 地址，避免任何跳转。Python 客户端会拒绝重定向。

成功请求的最小形状如下；这里的数值仅为**合成格式示例，不是你的记录**：

```json
{
  "source": "apple_health",
  "observations": [
    {"date": "2026-11-09", "metric": "steps", "value": 1234}
  ]
}
```

若你选择文件路径，可将第 7 步词典用“获取文本”（Get Text from Input）转换为 JSON 后，用“存储文件”（Save File）保存到自己的私有目录。打开文件确认它是 JSON 对象，并安全传至运行 Python 的电脑。不要用共享相册或公开链接传输健康数据。

## 其余指标怎样归一化

每项都应先选来源、检查健康读取权限、核对单位与归属日，再添加到 `observations`；没有可信读数就省略该项。下面是输入约定，不表示快捷指令可以对六种类型使用同一套“求和”。

| 字段 | 单位与每日值的含义 | 接口范围 |
| --- | --- | --- |
| `weight_kg` | 该日所选来源最后一次体重；不是当日体重之和 | 1–500 kg |
| `steps` | 该日已合并确认的总步数，必须是整数 | 0–200000 步 |
| `active_energy_kcal` | 该日活动能量，不包括静息/基础能量；若原单位是 kJ，先明确转换为 kcal | 0–30000 kcal |
| `sleep_minutes` | 按下文约定归入醒来日期的前一晚实际睡眠时长 | 0–1440 分钟 |
| `resting_heart_rate_bpm` | 该日所选来源的静息心率日读数；不是普通心率样本的平均值或总和 | 20–250 次/分 |
| `workout_minutes` | 该日运动记录时间区间去重、裁剪到当日边界后的总分钟；不是重复训练记录相加 | 0–1440 分钟 |

这些上限是输入校验范围，**不是健康目标或安全阈值**。某类型在你当前系统中无法查询或没有可信的日值时，可在“询问输入”中手动填写健康 App 已核对的日值；未知则不添加，不能把问答框的默认零当成实际测量。`value` 不能是字符串、布尔值、`null` 或无限大。

### 睡眠必须单独处理

本版本约定：`date=D` 的 `sleep_minutes` 表示**在 D 日早晨醒来的前一晚主睡眠**，不把它全部记在入睡日。初始提取窗口采用档案时区的 `D-1 18:00` 到 `D 12:00`，包含跨午夜部分，排除“卧床”“清醒”，保留“睡眠/未指定”“核心/浅睡”“深睡”“REM”等睡眠状态。

只选一个可信睡眠来源，先把区间裁剪到窗口，再按开始时间排序，把重叠和相邻区间合并，最后将合并后的秒数除以 60。不能同时相加概括的“睡眠”区间和它包含的各睡眠阶段，也不能将手表与其他 App 的重叠区间相加。此步骤是区间并集，普通“时长求和”无法完成。若快捷指令无法可靠实现，先在健康 App 核对前一晚实际睡眠分钟数，通过“询问输入”手动确认后再上传。

这个窗口是本同步约定，不是医学睡眠定义；不包含午睡，夜班或主睡眠延续到中午之后也不适用。遇到这些情况，先确定实际主睡眠的完整区间及醒来日，在自己的数据说明中记录调整，然后发送核对后的总时长，不要把被窗口截短的数值当完整睡眠。服务器只收到每日数字，无法替你识别阶段重叠或修复错误归属。整个窗口无数据时省略此指标。

## 上传已有 JSON 文件

项目根目录执行，令牌通过隐藏输入进入环境变量，避免写在命令历史中：

```bash
export HEALTH_API_URL='https://你的真实域名'
read -r -s -p 'API token: ' HEALTH_API_TOKEN
export HEALTH_API_TOKEN
.venv/bin/python scripts/sync_health.py /你的私有目录/health-daily.json
unset HEALTH_API_TOKEN
```

客户端会读取项目根目录的 `.env`，已导出的环境变量优先；不要把该私有配置加入版本管理。同机开发可省略 `HEALTH_API_URL`，默认 `http://127.0.0.1:8000`。远程 HTTP、URL 中的账号密码、查询参数、片段及所有 HTTP 重定向均被客户端拒绝。客户端使用证书校验，遵循运行环境的代理和受信 CA 配置；本机访问按环境需要设置 `NO_PROXY=localhost,127.0.0.1,::1`。非成功响应只打印状态码，不打印服务端内容或令牌。失败后检查服务、证书、令牌和文件，再手动重试。

文件大小不超过 1 MiB，每批 1–1000 项，每个日期及指标只能出现一次。可以一次同步多个日期；日期使用 `YYYY-MM-DD`，年份限 1900–9998，按档案时区的自然日汇总，睡眠除外按上述醒来日归属。不要上传原始样本或额外字段。重跑同一 `source/date/metric` 会**替换**已有快照，不会累加；更新当天合计时重新发送完整日值。省略某项不会删除服务器已有值，录错后需发送核对后的替换值。

## 设定自动化之前

手动成功后，可在“快捷指令 → 自动化 → ＋ → 特定时间”创建个人自动化，选择运行“健康每日同步”；支持的系统可选“立即运行”。自动化版本应移除交互日期选择，固定读取**前一个已经结束的自然日**，并保留来源、空数据和重叠检查。睡眠可在次日早晨运行后更新醒来日。Apple Watch 延迟同步的数据可稍后重跑，服务器的替换规则避免累加。

iOS 权限、锁屏状态、网络和动作支持可能影响自动执行，不能保证后台实时同步。先在手机锁定/解锁两种情况下自行验证，并保留失败后手动运行的办法。不要为了自动化绕过系统授权。撤销健康读取权限或删除个人自动化可停止后续导出；停用服务端令牌可停止上传。
